## 阶段详解

### 阶段1：参数收集

所有参数及默认值见 `assets/config.template.json`。关键参数权衡：

| 参数 | 低值（省成本） | 高值（求完美） |
|------|---------------|---------------|
| maxDiscussionRounds | 1（单轮） | 3（多轮收敛） |
| reviewExperts | 6人核心团 | 12人全员 |
| maxQualityIterations | 1 | 3 |
| targetScore | 70 | 90 |

**成本估算**（单集，6专家×2轮×2迭代）：
- 专家评审：6×2 = 12次轻量调用
- 整合：2次全量调用
- 重写：1次（专家）+ 2次（飞轮）= 3次全量调用
- 评分：3次全量调用
- 单集约 20次AI调用。10集约200次。建议用 lite 模型做评审，pro 模型做生成。

### 阶段2：大纲准备

5章节大纲的生成顺序（后章参考前章）：
1. **故事梗概** — 核心设定/主要人物/核心冲突/故事走向
2. **世界观设定** — 时代背景/势力分布/核心规则/地理
3. **人物小传** — 主角/女主/配角/反派，含性格/背景/弧线/口头禅
4. **整体大纲** — 三幕结构，分阶段关键情节节点
5. **分集故事线** — 每集核心故事+悬念钩子

大纲是大纲生成函数和剧集生成函数的共同上下文，必须先于剧集完成。

### 阶段3：逐集写作

#### (a) 生成初稿

输入：
- 完整大纲（确保人物/设定一致）
- 本集故事线（从分集线章节提取，提取不到则传整个章节）
- 上一集结尾（自然衔接，第1集无）
- 写作风格指令

输出：符合格式的初稿（短剧2-3场景/约1200字，小说约2000字）。

#### (b) 12专家子代理多轮评审（核心）

**为什么多轮**：单轮并行发言是"各自表态"，不是"讨论"。多轮让专家看到彼此意见后补充/反驳/修正，才是真正的"自行讨论"，能收敛出更优方案。

**子代理实现**（用户选定：真 Agent subagent）：
- 用 Agent tool 在单条消息中并行 spawn 多个子代理（每专家1个）
- `subagent_type: general-purpose`（需思考能力）
- 子代理 prompt = 专家 systemPrompt + 评审任务 + 上下文 + 输出要求
- 第2轮起增加"上一轮其他专家意见"段

**收敛检测**：每轮后可选地询问一个轻量子代理"专家意见是否已收敛"，收敛则提前结束，节省成本。

**整合**：把所有轮次意见交给整合模型，输出结构化方案：
- consensus（共识）
- disagreements（分歧）
- solutions（2-3个修改方案，含优缺点）

#### (c) 按评审意见重写

把整合方案作为修改指令，重写本集。约束：
- 只修改专家指出的问题
- 保持剧情主线和人物设定不变
- 输出完整内容（非片段）

#### (d) 质量飞轮迭代

**5维度评分**（0-100）：
- plot 情节合理性
- character 人物塑造
- pacing 节奏把控
- dialogue 对话质量
- consistency 设定一致性
- overall 综合（非简单平均）

**迭代逻辑**：
```
for i in 1..maxIterations:
    feedback = AI评分(当前内容)
    if feedback.score.overall >= targetScore:
        达标, 停止
    重写指令 = 把低分维度+改进建议转为修改指令
    当前内容 = AI重写(当前内容, 重写指令)
最终评分 = 最后一次评分
```

记录每集：集号/标题/最终内容/评分/迭代次数/是否达标/专家评审摘要。

### 阶段4：全局一致性检查

全集完成后，剧本审核专家扫描：
- 人物设定是否 OOC（跨集一致性）
- 时间线是否矛盾
- 地点描述是否一致
- 伏笔回收完整性
- 设定自洽性

输出格式：✅一致 / ⚠️警告 / ❌冲突 + 详细说明。

### 阶段5：输出

最终输出一个 Markdown 文件，包含：
- 完成报告（集数/平均分/各集评分表）
- 全局一致性检查报告
- 完整大纲
- 各集正文（带标题和评分）

用 present_files 交付。

## 定时续写机制

配合 WorkBuddy automation 实现定时写作：

1. **首次运行**：从 startEpisode=1 写到 endEpisode=N，输出文件含已完成集号。
2. **定时触发**：每次运行先读上次输出文件，解析已完成集号，从 N+1 续写到 N+批次大小。
3. **直到写完**：达到 totalEpisodes 后停止。

automation 配置见 `assets/automation-template.json`。

## 质量评分标准

| 分数段 | 含义 | 处理 |
|--------|------|------|
| 90-100 | 优秀 | 直接采纳 |
| 80-89 | 良好 | 达标，采纳 |
| 70-79 | 合格 | 可采纳，建议再优化 |
| 60-69 | 一般 | 必须重写 |
| <60 | 不合格 | 大改 |

默认 targetScore=80。追求精品可设 90（注意：越高迭代越多，成本越高）。
